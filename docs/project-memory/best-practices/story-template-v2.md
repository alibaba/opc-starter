# Story 模板 v2

> 版本: 2.0
> 更新日期: 2026-03-19
> 变更来源: MVP Retrospective（Epic 29-34）

---

## 变更说明

v1 → v2 主要变更：

1. **新增单元测试任务**：Dev 在 Story 开发期间必须编写单元测试
2. **明确测试边界**：定义需要测试和不需要测试的范围
3. **强化 Done 定义**：测试覆盖率成为 done 的必要条件
4. **QA 通知机制**：Story 完成后通知 QA 安排集成测试

---

## 测试边界指南

### 需要测试

| 类型 | 范围 | 示例 |
|------|------|------|
| 业务逻辑函数 | 计算类、转换类、校验类 | `formatFileSize()`, `validateSkillName()` |
| 组件事件处理 | onClick, onSubmit, onChange | 点击按钮触发正确 action |
| 状态管理 | store actions, selectors | 调用 action 后 state 正确更新 |
| API 调用 | 成功/失败分支 | 200 返回正确解析，500 正确处理 |
| 边界条件 | 空值、极限值、错误输入 | `null`, `undefined`, 空数组 |

### 不需要测试

| 类型 | 原因 |
|------|------|
| 第三方库内部逻辑 | 库已自测 |
| 纯展示组件样式 | 视觉测试覆盖 |
| 框架层面功能 | React 渲染、路由跳转 |
| 简单 getter/setter | 无逻辑分支 |

---

## 覆盖率要求

| 代码类型 | 最低覆盖率 | 目标覆盖率 |
|----------|-----------|-----------|
| 核心业务逻辑 | 80% | 100% |
| 关键路径（支付、权限、数据写入） | 100% | 100% |
| UI 组件 | 60% | 80% |
| 工具函数 | 80% | 90% |

## 与 AGENTS.md 集成

以下内容应同步写入 `AGENTS.md`：

```markdown
## 测试责任分层

| 测试类型 | 负责人 | 时机 | 范围 |
|----------|--------|------|------|
| 单元测试 | Dev | Story 开发期间 | 函数、组件、服务层逻辑 |
| 集成测试 | QA | Story 完成后 | 端到端流程、跨模块交互 |
| E2E 测试 | QA | Epic 完成后 | 用户完整旅程 |
```
