# AI 亲和度检查清单

本文档提供完整的检查清单和评分细则，用于系统性评估代码仓库的 AI 亲和度。

## 评分等级说明

| 等级 | 分数范围 | 说明 |
|------|----------|------|
| A | 90-100 | 优秀，AI 可高效协作 |
| B | 75-89 | 良好，大部分场景适用 |
| C | 60-74 | 及格，需要改进 |
| D | < 60 | 不及格，AI 协作困难 |

---

## 维度 1: 最小可运行环境（权重 15%）

**核心目标**: AI Coding 工具可在本地快速启动应用，验证修改效果，尽可能少依赖第三方服务

### 检查项

- [ ] **一键启动**
  - [ ] 有明确的启动命令（如 `npm run dev`）
  - [ ] 启动命令在 README 中有说明
  - [ ] 无需复杂前置配置即可运行

- [ ] **Mock 模式**（核心）
  - [ ] 支持 Mock 模式启动（如 `npm run dev:mock` 或环境变量开关）
  - [ ] Mock 可屏蔽后端 API 依赖（MSW / json-server / Mirage）
  - [ ] Mock 可屏蔽第三方服务依赖（支付、云存储、AI 等）
  - [ ] Mock 模式下核心功能可正常使用

- [ ] **环境变量管理**
  - [ ] 提供 .env.example 或 .env.local.example 模板
  - [ ] 文档说明必需和可选的环境变量
  - [ ] Mock 模式下无需真实 API Key 即可启动

- [ ] **依赖锁定**
  - [ ] 使用锁文件（package-lock.json / yarn.lock / pnpm-lock.yaml）
  - [ ] 可选：使用 .nvmrc / .node-version 锁定运行时版本

### 评分标准

| 分数 | 条件 |
|------|------|
| 4 | 一键启动 + Mock 模式完整 + 环境变量模板 + 依赖锁定 |
| 3 | 一键启动 + 有 Mock 模式或完整启动文档 + 依赖锁定 |
| 2 | 可启动但需要手动配置环境变量或部分依赖 |
| 1 | 启动依赖外部服务，无 Mock 方案 |
| 0 | 无明确启动方式或强依赖外部服务无法本地运行 |

> **架构适配说明**: 对于 BaaS 架构（如 Supabase + Edge Function + 纯前端），Docker/容器化不是必需项。核心评估点是能否通过 Mock 屏蔽后端依赖，实现本地独立开发和验证。

## 维度 2: 前后端解耦（权重 10%）

**核心目标**: 前后端可独立开发、调试、测试

### 检查项

- [ ] **Mock 服务**
  - [ ] 配置 MSW / json-server / Mirage 等 Mock 工具
  - [ ] Mock 数据覆盖主要 API
  - [ ] Mock 服务可独立启动

- [ ] **API 契约**
  - [ ] 提供 OpenAPI / Swagger 规范
  - [ ] 前后端共享类型定义
  - [ ] 接口变更有版本控制

- [ ] **独立调试**
  - [ ] 前端可不依赖后端启动
  - [ ] 后端可不依赖前端测试
  - [ ] 有独立的开发服务器配置

### 评分标准

| 分数 | 条件 |
|------|------|
| 4 | 完整 Mock 服务 + API 契约 + 独立启动脚本 |
| 3 | 有 Mock 服务，可独立调试 |
| 2 | 部分接口有 Mock |
| 1 | 强依赖后端服务 |
| 0 | 完全耦合，无法独立启动 |

- [ ] **类型覆盖**
  - [ ] 无 any 类型滥用

- [ ] **类型检查集成**
  - [ ] IDE 实时类型检查

  - [ ] pre-commit hook 检查类型

### 评分标准

| 分数 | 条件 |
|------|------|
| 4 | TypeScript strict 模式 + 无 any + 类型完整 |
| 3 | TypeScript 开启，少量 any |
| 2 | TypeScript 开启但配置宽松 |
| 1 | 仅部分文件使用 TypeScript |
| 0 | 纯 JavaScript 无类型 |

## 维度 4: 单元测试（权重 15%）

**核心目标**: 核心逻辑有测试保护，修改可快速验证

### 检查项

- [ ] **测试框架**
  - [ ] 配置 Jest / Vitest / pytest 等框架
  - [ ] 测试可一键运行

- [ ] **覆盖率**
  - [ ] 配置覆盖率报告
  - [ ] 总体覆盖率 > 60%
  - [ ] 核心模块覆盖率 > 80%

- [ ] **测试质量**
  - [ ] 测试命名清晰

  - [ ] 避免测试间依赖

### 评分标准

| 分数 | 条件 |
|------|------|
| 4 | 覆盖率 >80% + 核心路径 100% + 测试质量高 |
| 3 | 覆盖率 60-80% + 核心路径有覆盖 |
| 2 | 覆盖率 40-60% |
| 1 | 有测试但覆盖率 <40% |
| 0 | 无单元测试 |

## 快速评分计算

使用以下公式计算总分：

```
总分 = (维度1得分/4 × 15) + (维度2得分/4 × 10) + (维度3得分/4 × 15) + 
       (维度4得分/4 × 15) + (维度5得分/4 × 10) + (维度6得分/4 × 10) + 
       (维度7得分/4 × 8) + (维度8得分/4 × 7) + (维度9得分/4 × 5) + 
       (维度10得分/4 × 5)
```

**示例计算：**
- 维度1: 3分 → 3/4 × 15 = 11.25
- 维度2: 2分 → 2/4 × 10 = 5
- ...
- 总分 = 各维度得分之和
